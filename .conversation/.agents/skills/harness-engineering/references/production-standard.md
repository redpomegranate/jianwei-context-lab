# 生产级 Harness 标准

版本 0.2.0。本文是基于书中五要素扩展的工程规范，不宣称以下全部要求来自原书。
目标：可控制、可恢复、可追责、可测量、可安全演进。
每项必须有负责人、强制位置、验证器、证据和失败处置。仅文档说明不能证明实现。
架构按风险裁剪，控制目标不得默默省略；不适用项要说明替代保障并经独立审查。

## G01 服务目标与风险

- 描述服务用户、业务成功定义、失败影响、数据敏感度、租户及外部依赖边界。
- 分开测量接口可用、业务完成、语义质量、过程合规；200 响应或生成文本不算任务成功。
- 定义各 SLI 的分子/分母、窗口、超时与未知结果如何计入；不能剔除失败来提高指标。
- 为延迟分位数、业务成功、队列年龄、恢复时间、成本设定有负载依据的 SLO。
- 定义错误预算及消耗后的动作：暂停发布、降级、限制自主写入或人工接管。
- 定义 RTO/RPO 和数据损失容忍度；安全违规不能拿可用性错误预算抵扣。
- 未知峰值/目标可先压测探索，但上线前由责任人确定范围与容量上限。

## G02 信任边界与能力授权

- 输出数据流/信任边界图，覆盖用户、检索、文件、工具、模型供应商、插件及运维入口。
- 工具网关每次调用校验主体、租户、目标对象、动作、参数、当前状态与授权有效期。
- 用户/租户身份来自认证上下文，不接受模型自行指定可信身份。
- 能力默认拒绝，区分读/写/发布/资金/删除；工具版本或权限变化需要重新审查。
- 高风险审批绑定主体、动作、资源、规范化参数摘要、有效期及唯一审批 ID；
  执行前再次检查当前权限与资源版本。参数改变、审批过期或撤销均须重新审批。
- 代理/子 Agent 权限只能收窄，不能通过委托获得父任务没有的权限。
- 代码执行采用沙箱、资源限制及文件/网络白名单；控制外连、SSRF 与数据外传。
- 外部检索、工具描述及输出均属不可信证据；schema 合法不等于来源可信或内容安全。
- 密钥服务端托管、最小权限、轮换和撤销；禁止把生产凭证放进模型上下文。
- 敏感内容送模型前检查供应商、地区、保留/训练政策与授权；故障切换不绕过数据政策。
- 安全策略服务不可用时，高风险动作 fail closed，并保留只读/人工替代路径。

## G03 持久执行与并发正确性

- 由服务端状态机裁决迁移；定义非法迁移、终态、暂停、等待审批、取消与过期。
- 持久化 run、step、attempt、事件序号、父子关系、业务版本与全部执行配置版本。
- 调度可按至少一次投递设计；消费者必须容忍重复、乱序、延迟和重放。
- 多 worker 用租约/心跳及 fencing token 或等效机制防止失效 worker 写入。
- 数据库事务或 CAS 保护状态；子任务失败、超时、取消的传播语义必须明确。
- 检查点不只是模型对话：应包含已确认副作用、未决调用、预算、审批状态与恢复位置。
- 模型随机性意味着恢复不保证逐字复现；确定性重放使用录制结果，不重执行真实写操作。
- 重启恢复前对账；恢复进程也遵守原任务的总期限、权限撤销和预算。

## G04 副作用与结果不确定性

- 幂等键限定租户、动作、业务请求及版本，定义保存期；同键不同参数必须拒绝。
- 区分未提交、已提交、失败、结果未知；模型不得把结果未知报告为失败或成功。
- 本地提交与消息投递使用事务/outbox 或等效保证；跨系统写入配置对账流程。
- 不能幂等且不可查询的高影响动作，禁止自动重试；冻结待人工核对。
- 补偿不是数据库回滚的同义词：定义补偿授权、可能失败、次数与最终人工责任。
- 取消只能阻止后续可阻止动作；已发生副作用要告知并按授权补偿，不伪称“已撤销”。

## G05 负载、故障与成本控制

- 按租户、用户、模型、工具设置准入、并发、速率、队列与总预算限制。
- 对队列定义最大长度/年龄、背压、拒绝策略及公平性，防止单租户耗尽资源。
- 截止时间向子任务传播；重试指数退避带抖动，服从全局重试预算，避免放大故障。
- 断路器定义打开/半开/恢复条件；隔舱隔离供应商、工具和租户故障。
- 长任务必须匹配平台执行时限；需要时用持久 worker/任务服务，不把请求超时当任务取消。
- 成本预算含子任务和重试；并发前预留预算、完成后结算，限制 token/调用数作硬兜底。
- 供应商切换、缓存及降级须分别验证质量、权限、租户键和隐私兼容性。
- 进行峰值、突发、持续负载与依赖故障压测，报告负载模型、拐点及恢复能力。

## G06 上下文与记忆治理

- 给上下文设大小、来源、可信度、时间戳、租户和版本；超长时明确截断/压缩策略。
- 压缩不得丢失用户限制、审批范围、未决写操作、关键证据和预算；保留来源引用。
- 检索与缓存同样执行租户过滤和权限复核；测试跨租户缓存碰撞与过期授权。
- 记忆写入是受控副作用：来源可追溯、有作用域/有效期、冲突处理、删除与纠错路径。
- 未验证网页指令和模型反思不能自动升级为可信长期规则，防止记忆投毒。
- 记录输入/提示词构造版本与脱敏证据，确保问题可定位而不复制全部隐私内容。

## G07 数据生命周期与灾难恢复

- 定义分类、最小采集、传输/静态加密、访问审计、保留和删除策略。
- 覆盖业务库、缓存、队列、向量索引、日志、供应商数据和备份；不得只删除主表。
- 备份与恢复权限隔离，定期在隔离环境还原并验证业务一致性与实测 RTO/RPO。
- 恢复旧备份后重放删除记录/墓碑，避免已删除内容重新进入服务。
- schema/事件格式演进使用兼容读写与 expand-contract；考虑旧 worker、旧检查点与在途任务。
- 不可逆迁移需要备份、演练、前向修复方案及审批，不能假设代码回滚能还原数据。

## G08 观测、审计和事件响应

- 指标/日志/trace 以 run/step/tool/tenant 的受控关联键串联；限制高基数与敏感标签。
- 普通调试遥测可采样；关键授权、审批和写入审计不能因采样而丢失。
- 审计日志限制修改、具备篡改检测；审计链断裂时高风险动作停用或使用可靠本地缓冲。
- 告警涵盖业务失败、预算燃尽、队列积压、未知副作用、越权、预算异常和孤儿运行。
- 告警必须有接收人、严重级别、响应时限、升级路径和 runbook，且真实演练通知链。
- 明确服务 owner、值班或小团队等效责任人；不能只“转人工”而无人接收。
- 支持全局/租户/工具/版本级停用开关；演练停止新任务和隔离在途危险动作。
- 事故复盘记录时间线、首错、影响范围、恢复证据及回归行动，不仅归咎于模型。

## G09 评估与安全门禁

- 正常/边界/对抗/故障/恢复/长程场景覆盖真实任务分布，明确每个测试的 oracle。
- 权限、状态、副作用、预算由确定性检查判定；语义正确性结合标注集与人工抽检。
- 评估器独立于候选写权限；LLM judge 需与人工对齐并监测版本漂移，不能单独裁决安全。
- 保留集不参与调参，真实用户样本须授权脱敏；生产 shadow 不得重执行真实写操作。
- 对随机输出多次运行和配对对比，报告置信区间或波动；零观测违规不证明零风险。
- 指标同时覆盖业务成功、策略违规、错误外部动作、恢复成功、延迟与成本。
- 任一安全关键回归、缺失证据、未演练恢复均阻断发布，而非平均分达标即可。

## G10 可控发布与持续运行

- 发布单元绑定代码、模型、提示词、Skill、工具 schema、策略、记忆/检索配置及数据版本。
- 依赖锁定、构建可追溯、秘密/依赖漏洞扫描；生产环境与测试环境权限隔离。
- 先离线门禁，再安全 shadow/内部流量，再按租户固定路由的 canary，最后扩量。
- 上线前确定各阶段样本量/时长、指标阈值、停止条件、负责人和自动/人工回退方式。
- 版本回退考虑在途任务和数据兼容，旧运行保持版本固定或走经过测试的迁移。
- 验证回退后业务与安全指标恢复；不能只检查旧进程启动成功。
- 持续监测模型/工具漂移和供应商变更，触发重评估；业务 Agent 不修改自己的发布裁判。
- 生产就绪是指定范围和时点的证据结论，变更或超出负载范围须重新评审。
