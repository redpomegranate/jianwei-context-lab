# 「见微」社会情境认知训练器适配

这是针对当前 PRD/MVP 讨论的工程建议，不是用户已批准的最终架构。
基础方向：移动端优先 Web App；可采用 Next.js、Supabase；后续 Vercel 部署。
本 Skill 不自动连接数据库、执行迁移或部署。

本适配仅规定业务差异，不能替代 production-standard 的生产控制。
MVP 可以缩小业务功能与负载范围，不能豁免租户隔离、副作用安全、
恢复证据、告警责任及发布回退。生产标准存在缺口时结论仍为 NOT_READY。

## 两层治理分别实现

开发 Harness：任务契约 → 小步实现 → 测试 → 独立审查 → 经授权发布。
产品 Harness：用户输入 → 状态与权限校验 → AI 候选输出 → 验证 → 用户确认 → 持久化。
产品 AI 不获得 SQL、部署或任意代码执行权限；开发 Agent 的权限不能泄露给产品 AI。
Supabase MCP 是开发期管理入口；线上使用服务端/API/SDK 与 RLS，不依赖聊天 MCP。

## 首版架构：明确工作流，而不是开放自主循环

四类模型节点：整理与追问、替代假设、预测辅助、复盘辅助。
每个节点有独立 schema、输入白名单、模型/提示词版本、超时及安全的失败回退。
AI 只返回候选内容，由确定性服务执行获授权的业务变更。
能用普通请求完成就不引入长任务队列；跨请求恢复至少持久化 run/step 和业务状态。

## 必须强制的不变量

| 规则 | 强制位置 | 验收 |
| --- | --- | --- |
| 用户只能读写自己的事件及子记录 | 服务端身份校验 + RLS/关联所有权约束 | 两个测试账号的越权读写均失败 |
| 先记录用户解释或“暂不知道”，再展示 AI 假设 | 服务端状态机 + UI | 绕过 UI 调用接口也不能跳步 |
| 模型提取的是“用户报告的事实”，不是独立证实事实 | 输出 schema、原文证据引用、用户确认 | 新增事实无证据时拒绝采纳并保留草稿 |
| 预测必须含可观察事件、概率、期限、判定标准 | 服务端/schema/数据库 | 缺失字段不能提交 |
| 提交后锁定预测及当时分析快照 | 数据库约束/受控事务 | update 被拒；修订创建新版本 |
| 未知结果不能当作未发生 | 结果枚举与指标查询 | 无法判断样本不进入二元预测成绩 |
| AI 不替用户决定概率、判定动机或自动确认复盘 | UI 确认 + 受限写入接口 + 语义评估 | 模型输出无法直接推进用户确认状态 |
| 重复点击和超时重试不生成重复预测/复盘 | 幂等键 + 唯一约束/事务 | 并发提交仅产生一个有效结果 |
| 隐私人际材料不进入默认调试日志 | 日志白名单、脱敏测试 | 日志不含原始事件/密钥 |

“读心”等语义约束不能只靠关键词黑名单，使用来源核对、行为评估与人工抽检。
概率属于可观察事件，不能把可能共存的动机假设强制归一成 100%。
保留用户行为可能影响结果的字段，不把预测命中当作证明动机。

## 辅助数据建议

在业务五表之外，按实际需求增加：
- `agent_runs`：用户、事件、状态、模型/提示词/策略版本、预算、开始/结束、失败类别。
- `agent_steps`：run、节点、尝试次数、幂等标识、脱敏结果摘要、验证状态、时间与用量。

两表同样需要 RLS 和有限保留期；不默认保存原始私密提示词或完整模型消息。
私有内容的删除应覆盖派生分析、关联记录与遥测引用，备份保留限制需对用户说明。
必要正文只保存在授权的业务数据中，观察系统记录受控引用而非复制全文。

## 发布前证据

至少覆盖跨用户访问、并发重复、锁定绕过、注入指令、schema 错误、限流、
写入结果未知、运行重启、取消和日志泄漏。
测试数据用合成案例；真实记录进入评估集须另有授权并脱敏。
先内部试用，再根据失败轨迹修订提示词；不让线上 AI 自动修改正式 Skill。
