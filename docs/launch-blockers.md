# 上线前阻塞项

当前是可联调的 MVP，不是已通过生产验收的服务。未发布至 Vercel 或其他平台。

## Supabase 邮箱认证

Supabase 默认 SMTP 只向组织成员邮箱发信，不适合公开注册。上线前需要：
1. 在 Supabase Authentication / URL Configuration 配置 Site URL 和允许的登录、注册、密码恢复回跳 URL（应用根路径）。
2. 使用经过验证的 SMTP 服务与发信域名，保留邮箱验证。
3. 用真实测试邮箱走通注册确认、登录、退出、恢复密码和会话过期。

当前 MCP 未提供修改 Auth 配置的接口；这些配置未自动完成。不要关闭邮箱验证来掩盖问题。
参考：https://supabase.com/docs/guides/auth/auth-smtp

## Harness 生产门禁

- 运行记录目前经用户作用域 RPC 管理，不能作为不可篡改的服务端审计证据。发布前需要服务端专用可信写入能力与独立审计存储。
- 明确 SLO、峰值容量、费用预算、负责人及告警接收人；执行负载和依赖故障演练。
- 完成供应商的数据地域、保留和训练政策审核及隐私告知。
- 明确保留和删除周期，包括配额账本、备份与供应商数据；完成备份恢复与删除重放演练。
- 完成跨用户真实认证端到端验证、模型语义/注入评估和独立安全检查。
- 为 Vercel 配置正式模型访问方式，不能假设 Replit 专用 AI 代理凭据能在外部托管上直接使用。
- 预发布与生产环境隔离，灰度、回退以及在途请求兼容方案需验证。

已经通过的局部检查不替代以上门禁。详细实现约束见 backend-constraints.md。
